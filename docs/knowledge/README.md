# knowledge/ — Team Knowledge Base

**Purpose:** Record distilled team knowledge, best practices, and common solutions.

## What Goes Here

Knowledge entries capture:
- Lessons learned and best practices
- Common troubleshooting solutions
- Development tips and tricks
- Team conventions and standards
- Reference materials and guides

## Format

Knowledge entries should be:
- Concise and actionable
- Self-contained (can be read independently)
- Include examples where helpful
- Reference related ADRs/DRs when applicable

## Naming Convention

Use descriptive names: `TOPIC-description.md` (e.g., `LaTeX-compilation-tips.md`)

## Example Entries

```
- Beamer-customization-guide.md
- LaTeX-troubleshooting.md
- Slide-creation-best-practices.md
- Git-workflow-tips.md
```

## Not

This is NOT for:
- Decisions that belong in ADR/DR
- Investigations that belong in EIR
- Execution experience that belongs in RET

Use this for accumulated wisdom that helps the team work effectively.

# ADR-0001: Migrate from Custom DSL to Standalone Standard LaTeX

**Status:** Accepted
**Date:** 2026-02-24
**Author:** Qirui Li (architect-interviewed), documented by Architect agent
**References:** AA-0001 (Slide System Architecture Analysis)

---

## Decision

Migrate all 43 content `.tex` files from the current custom DSL (packaga.tex + unicodechar.tex) to standalone standard LaTeX/Beamer. Each file will become a self-contained, independently compilable document. The shared infrastructure files (packaga.tex, unicodechar.tex, compile_all_tex.py) will be deprecated and eventually removed.

---

## Context

### Why this decision is needed now

The slide system was built over 10 years (2016–2026) by a single author using custom DSL layers optimized for human authoring speed in a pre-AI workflow (vim + custom macros). The system now needs to support AI-assisted maintenance by the Engineer agent (Sonnet), who cannot reliably parse or generate the custom syntax.

### Current state

- **43 content modules** depend on a monolithic `packaga.tex` (~1700 lines) for all macro definitions
- **unicodechar.tex** provides a custom Unicode tokenizer that replaces standard LaTeX commands with Unicode characters
- Content files have no `\documentclass`, no `\usepackage` — they cannot compile alone
- Custom DSL includes: frame system (`\aaa`/`\a`/`\aa`), matrix shorthand (`\m`/`\t`), theorem environments (`\[defi]`/`\[prop]`), layout helpers (`\[columns]`/`\co`), and more
- The author is the only person who can maintain or modify the slides
- AI tools (Claude, etc.) cannot reliably read, modify, or generate the custom DSL

### Author's stated motivation

> "现在是AI时代了，一切都变了。标准LaTeX让AI能更好地辅助维护。"
> (Now it's the AI era, everything has changed. Standard LaTeX enables better AI-assisted maintenance.)

The custom DSL was built because the author "couldn't type `\begin{frame}` repeatedly" in the pre-AI era. With AI assistance, this productivity concern no longer applies.

## Scope of Migration

### What is deprecated (full list)

| Component | Location | Replacement |
|-----------|----------|-------------|
| Frame DSL: `\aaa{Title}`, `\a`, `\aa` | packaga.tex:254–295 | `\begin{frame}{Title}...\end{frame}` |
| Matrix DSL: `\m` | packaga.tex:200–230 | `\begin{pmatrix}...\end{pmatrix}` |
| Table DSL: `\t` | packaga.tex:200–230 | `\begin{tabular}...\end{tabular}` |
| Theorem DSL: `\[defi]{}`, `\[prop]{}`, `\[thm]{}`, etc. | packaga.tex:62–197 | Standard `\begin{definition}...\end{definition}`, `\begin{proposition}`, etc. |
| Layout DSL: `\[columns]{}`, `\co5` | packaga.tex | `\begin{columns}\begin{column}{0.5\textwidth}...\end{column}\end{columns}` |
| Positional matrix constructors: `\mm`, `\mmm`, `\cc`, `\ccc`, etc. | packaga.tex:370–860 | `\begin{pmatrix}...\end{pmatrix}` with explicit content |
| Unicode tokenizer | unicodechar.tex (entire file) | Standard LaTeX: `\mathbb{R}`, `\times`, `\in`, etc. |
| Bold matrix: `\bm` | packaga.tex | Standard `\begin{bmatrix}` |
| Duplicated emoji blocks | packaga.tex:866–916 | Remove duplicates |
| `compile_all_tex.py` | root | No longer needed; `pdflatex <file>.tex` directly |
| `\xequal{}` | packaga.tex | `\overset{\text{...}}{=}` or `\xrightarrow{}` |

### What is preserved

| Component | Reason |
|-----------|--------|
| **Red/Blue/Purple classification macros** (`\LI`, `\LS`, `\iso`, `\inj`, `\sur`, `\li`, `\ls`, `\inve`, etc.) | Core pedagogical system grounded in "万物都是映射" philosophy. Non-negotiable. Copy into each file that uses them. |
| **Emoji definitions** (`\milk`, `\coffee`, `\bean`, `\leaf`, `\lemon`, `\cow`, `\tea`, `\soup`, `\cola`, `\bento`, etc.) | Pedagogical content — the coffee-shop metaphor is integral to the teaching narrative. Copy into each file that uses them. |
| **Character macros** (`\no`, `\buxie`, `\sinister`) | Pedagogical dialogue characters. Copy into each file that uses them. |
| **Mathematical operator macros** (`\End`, `\Hom`, `\GL`, `\Spec`, `\Aut`, etc.) | Standard mathematical notation shortcuts. Copy into each file that uses them. |
| **All slide content** | Mathematical exposition, examples, exercises, proofs, narratives — immutable. |
| **Curriculum ordering** | The sequence in main.tex reflects deliberate pedagogical arc. |
| **Beamer + Metropolis theme** | Keep the same visual theme. Change only if compilation difficulties arise. |
| **main.tex as index** | Preserved as an entrance/navigation index. Not used for compilation. |
| **`\x{}` highlight macro** | Simple `\textcolor` wrapper, useful. Define in each file. |
| **TikZ diagrams** | Standard LaTeX, no migration needed. |

### Handling of preserved macros

Classification macros, emoji definitions, and other preserved macros will be **copied directly into each file's preamble** that uses them. This creates duplication across files, which is accepted by the author in favor of file independence:

> "I accept this repetition until any time in the future I decide otherwise. I wish every file to stand alone."

## Migration Strategy

### Approach: One-by-one, learn-as-you-go

Migration proceeds **one module at a time**. The author migrates the first module (pilot), makes modifications, and the team uses lessons learned to establish patterns for subsequent modules. The Engineer agent executes remaining migrations following the established pattern.

### Workflow per module

```
Author/Architect ──defines scope──→ Engineer ──migrates module──→ Author ──verifies PDF──→ next module
```

1. **Engineer** converts the module to standalone standard LaTeX
2. **Engineer** writes a DR (Design Rationale) documenting any non-obvious conversion decisions
3. **Author** compiles and verifies the PDF output manually
4. Lessons learned feed into the next module's migration

### Pilot module

**`rowoperation.tex`** — selected because:
- Author needs it for class (urgent, within 3 hours of this decision)
- Contains nearly all DSL features: `\aaa`/`\a`/`\aa`, `\m`, `\t`, `\[defi]`/`\[prop]`/`\[cor]`, `\[columns]`/`\co`, emoji characters, `\xequal`, `\x{}` highlights
- Rich test case for establishing migration patterns

### Priority after pilot

The author will decide module priority based on teaching schedule. There is no fixed migration order for remaining modules — the author may request specific modules urgently for upcoming lectures, while others can wait.

## Target File Structure (post-migration)

Each migrated `.tex` file will have this structure:

```latex
\documentclass[10pt]{beamer}
\usetheme{metropolis}

% ── Packages ──
\usepackage{amsmath,amssymb,amsthm}
\usepackage{tikz}
\usepackage{graphicx}
% ... (only packages actually used by this file)

% ── Theorem environments ──
\newtheorem{proposition}{Proposition}
% ... (only environments actually used by this file)

% ── Classification macros (if used) ──
\newcommand{\LI}{\color{red}\textbf{LI}}
% ... (copied from packaga.tex, only those used)

% ── Emoji definitions (if used) ──
\newcommand{\milk}{...}
% ... (copied from packaga.tex, only those used)

% ── Other preserved macros ──
\newcommand{\x}[1]{\textcolor{...}{#1}}
% ...

\title{Topic Title}
\begin{document}
\maketitle

\begin{frame}{Frame Title}
  ...
\end{frame}

% ... standard Beamer frames ...

\end{document}
```

## Consequences

### Positive

1. **AI-maintainable**: Engineer agent can read, modify, and generate standard LaTeX without DSL knowledge
2. **File independence**: Each file compiles with `pdflatex <file>.tex` — no shared infrastructure dependency
3. **Lower bus factor**: Any LaTeX-literate person (or AI) can maintain the slides
4. **Simplified build**: No need for `compile_all_tex.py` or the `main.tex` toggle workflow for compilation
5. **Standard tooling**: LaTeX linters, formatters, and editors work out of the box

### Negative

1. **Macro duplication**: Classification macros, emoji definitions repeated across files. Accepted trade-off for independence.
2. **Verbosity**: Standard LaTeX is more verbose than the DSL (e.g., `\begin{pmatrix}a&b\\c&d\end{pmatrix}` vs `\m ab,cd.`). Acceptable because AI generates it.
3. **Migration effort**: 43 modules to migrate, each requiring manual verification. Mitigated by one-at-a-time approach.
4. **Temporary inconsistency**: During migration, some files use DSL, others use standard LaTeX. main.tex and packaga.tex must remain until all modules are migrated.

### Risks

1. **PDF output mismatch**: Migrated file may not produce identical visual output. Mitigated by author's manual verification.
2. **Missing macro**: A DSL macro may be missed during conversion. Mitigated by compilation check — missing macros cause pdflatex errors.
3. **Emoji rendering**: Emoji definitions may need adjustment for standalone compilation. Will be resolved during pilot.

---

## Alternatives Considered

### Alternative A: No migration — continue using custom DSL

**Rejected.** The custom DSL was optimized for a single human author in the pre-AI era. It blocks AI-assisted maintenance, which is now the primary workflow. The author is the only person who can modify the slides, creating an unsustainable bus factor.

### Alternative B: Automated batch conversion script

**Rejected.** Each module has unique content patterns, metaphors, and edge cases. A conversion script would produce output that still requires manual verification of every file. The one-by-one approach allows learning and catches issues early, with the same total verification effort but better quality control.

### Alternative C: Switch to a different presentation tool (Typst, Reveal.js, etc.)

**Rejected.** LaTeX/Beamer is the mature standard for mathematical presentations. The content is deeply invested in LaTeX math typesetting. Switching tools would require re-learning with no clear benefit. The problem is the custom DSL layer, not LaTeX itself.

## Implementation Notes for Engineer

### DSL-to-standard conversion reference

| DSL Pattern | Standard LaTeX Equivalent |
|-------------|--------------------------|
| `\aaa{Title}` ... `\a` ... `\aa` ... `\aaa` | `\begin{frame}{Title}...\end{frame}` per slide |
| `\a{Title}` | `\begin{frame}{Title}` |
| `\a\aa` | `\end{frame}\begin{frame}` (continue previous section) |
| `\m ab,cd.` | `\begin{pmatrix}a&b\\c&d\end{pmatrix}` |
| `\m ab,cd,ef.` | `\begin{pmatrix}a&b\\c&d\\e&f\end{pmatrix}` |
| `\t{}AB,C12,D34.` | `\begin{tabular}{cc}\hline A&B\\\hline C&1&2\\D&3&4\\\hline\end{tabular}` (inspect packaga.tex for exact semantics) |
| `\[defi]{...}` | `\begin{definition}....\end{definition}` |
| `\[prop]{...}` | `\begin{proposition}...\end{proposition}` |
| `\[cor]{...}` | `\begin{corollary}...\end{corollary}` |
| `\[columns]{...}` | `\begin{columns}...\end{columns}` |
| `\co5` | `\begin{column}{0.5\textwidth}` |
| `\co{45}` | `\begin{column}{0.45\textwidth}` |
| `\x{text}` | `\alert{text}` or equivalent highlight |
| `\xequal{label}` | `\overset{\text{label}}{=}` |
| `\li` / `\ls` | Classification tags (preserve macro, define in preamble) |

### Frame generation semantics (`\aaa`/`\a` system)

The `\aaa{Title}` macro begins a new **section** of slides. Content between `\a` markers becomes individual frames. The `\aa` continues within the same section (generates a frame without a new title — uses the previous title or a continuation). The second `\aaa` (or `\aaa{New Title}`) terminates the previous section.

**Key rule:** Count the `\a` and `\aa` markers to determine frame boundaries. Each `\a{Title}` or `\a\aa` pair typically starts a new frame.

### Verification checklist (per module)

- [ ] File compiles with `pdflatex` standalone (no packaga.tex dependency)
- [ ] All frames render correctly
- [ ] All mathematical expressions display correctly
- [ ] Classification colors (red/blue/purple) appear correctly
- [ ] Emoji characters render correctly
- [ ] TikZ diagrams render correctly
- [ ] No LaTeX warnings about undefined commands
